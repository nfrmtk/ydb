# min_max индекс

## Что такое локальный индекс пропуска {#local-index}

Локальный индекс — вспомогательная структура, хранящаяся вместе с данными таблицы и применяемая на этапе чтения из хранилища. Она не материализует отдельную индексную таблицу и не подключается в запросе через `VIEW` (в отличие от глобальных индексов).

В {{ ydb-short-name }} реализован `min_max` — локальный индекс пропуска для [колоночных таблиц](../glossary.md#column-oriented-table): при каждом сканировании оптимизатор запросов и слой хранения используют его, чтобы пропускать фрагменты данных, не содержащих нужных значений.

## Как работает `min_max` {#how-it-works}

{% include [min_max_concept.md](../datamodel/_includes/min_max_concept.md) %}

При чтении с условием фильтрации на индексируемой колонке движок проверяет для каждого фрагмента данных:

* Для условий вида `col = value`: если `value < min` или `value > max`, фрагмент пропускается.
* Для условий вида `col < value`: если `value <= min`, фрагмент пропускается.
* Для условий вида `col > value`: если `value >= max`, фрагмент пропускается.
* Аналогично для `<=`, `>=` и `BETWEEN`.

Эффективность зависит от того, насколько значения индексируемой колонки коррелируют с порядком хранения данных: чем слабее перекрываются интервалы `[min, max]` соседних фрагментов, тем больше фрагментов можно пропустить.

## Когда применять `min_max` {#when-to-use}

* Когда значения колонки коррелируют с первичным ключом или порядком загрузки данных (например, временны́е метки событий, монотонно возрастающие идентификаторы).
* Когда на фрагмент приходится небольшое число различных значений (например, колонка `source` при пакетной загрузке от одного источника).
* Для ускорения запросов с условиями `=`, `<`, `<=`, `>`, `>=` и `BETWEEN` на не-ключевых колонках.

Если значения в колонке распределены по фрагментам случайно и равномерно (интервалы `[min, max]` сильно перекрываются), `min_max` не даст значительного выигрыша.
